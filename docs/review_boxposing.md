# Review: the posing box cut in (`PSP_BOXPOSING=1`)

Off by default: a default build is the old path, byte for byte the rebase's. With the switch, every object's node matrices and bounding sphere come from the posing box (`psp/src/box_posing.c`, v0: the walk) in place of the engine's walk. The design is `docs/box_posing.md` §6c.

**The cut-over** (`psp_fixups.py`, `FIXES_BOXPOSING`, registered after the capture's group):
- In `object_compute_node_matrices_with`, at the point where the capture records the box's inputs (after the decode, the overlays, the object's scale, the type's preprocess and the interpolation), `psp_box_pose(...)` runs and `goto psp_box_posed` skips the engine's validity checks, its node walk and its bounding sphere. The label sits after the sphere, so NMSKIP's note, the spheres' copy and the capture's exit hook run as before, and a capture build with the box records the box's own outputs.
- Objects placed with no model take the same route (`model` NULL, flag 32), so no object falls back to the engine's walk.
- `psp_box_pose` gathers the object's flags and place exactly as the capture does (`psp_cap1.h`'s posing records): world-relative, mirrored, attached and the parent's mirror, the physics' centre of mass negated, origin and bounding offsets, radius and scale. It writes the sphere back to the object.
- `objects_initialize_for_new_map` calls `psp_box_posing_forget()`: a plan is keyed by the model's address, which only means something within one map.

**The glue** (`psp/src/psp_boxposing.c`, no engine header): 96 plans a map, found through 256 slots by the model's address (POSEK found 32-63 posed models a map). A model past the room still poses through the box, from a plan made for that call, and the count goes to the log at the map's end (`boxposing:`). The place is copied field by field into `struct box_posing_object`, not as one 20-float block, so no copy runs past a member.

**What the switch leaves out:** the old path's levers on posing's ground (POSEK's plan walk, the pose memo, PSC's locals, NRCHK's root test and its error report, the node prefetch, VFPUPOSE's products) all sit inside the skipped walk.

**Proof so far:**
- Emulator [E]: play and both seeds identical every tick on b30_play2, b40_play1 (to ~6,000 ticks) and c20_play1; pictures inside one build's run spread; strict 0; 0 failed requests to the pads' ends (the lab's boxpose1 and boxpose2).
- PSP-3000 [M]: **not exact**. Play differs from tick 0 against the old path, and the seeds part at tick 1,249. The emulator's VFPU rounds as its FPU and the PSP's doesn't, and the box multiplies on the FPU where the old path's products run on the VFPU. With the game's VFPU forms off, the PSP and the emulator replay the same pad bit for bit (findings `pads_part_on_the_emulators_vfpu`).
- **Price:** +1.56 ms a tick against the old path on b30_play2, read under statecrc (findings `boxposing_inframe_b30_psp3000`). Re-run without statecrc, with `timerson` (the lab's sierra-hw 43154677709 / 43154710553): the tick +2.04 ms (+5.2%), the bipeds' node matrices 195 -> 225 µs an update; but the box's runs play a different fight (26.1 bipeds a tick against 24.6), since the box isn't exact on the PSP, so neither figure is like for like yet. **Like for like** (both sides with the VFPU forms off, the same fight bit for bit; sierra-hw 43167774865 / 43167800997): the bipeds' node matrices -8% an update (253 -> 233 µs), the tick +0.78 ms (+1.9%) as the rest of the tick rises, read as the old build's layout and profile on the box's build.

**Known limits:** a strict (`PSP_PGO_STRICT=1`) new-only build refuses to link until the profile is counted with the box in (`psp_box_pose` and the glue have no counts). The box's maths is v0's scalar FPU form; §8's VFPU kernel is the next step the lead weighs.

**Means A** (builder/posing-ab; `docs/box_posing.md` §6d):
- `psp_box_pose` (psp_fixups.py, FIXES_BOXPOSING) hands the box pointers to the object's position, forward and up, its parent's node matrix and its sphere: nothing is gathered or copied a pose. Its plan is found by the object definition, and made the first time with the definition's constants (the centre of mass negated when the model has physics, the origin and bounding offsets, the radius).
- `psp_boxposing.c`: a plan is the walk and the definition's `struct box_posing_place` side by side (128 a map). `box_posing_pose_ref` takes the place by reference; `box_posing_pose`, the harness's entry, now builds the same reference from its record, so the harness and the game run one path.
- `box_posing.c`: `plan->whole` is set when the walk visits every node of the model once; only then does `claim()` take the node block's whole lines with `cache 0x18` before the walk (cached user memory only). A claimed line's bytes are undefined until stored; the walk stores every byte of the block and reads only nodes it has stored. `boxposeclaimoff` turns the claims off for an A/B in one build.
- The maths is v0's, term for term: exact against the old path wherever v0 was.
- **Priced in frame (2026-11-12 19:2x)** [M, PSP-3000, the lab's sierra-hw 43335341419 / 43335363541]: with each side's own counts and layout, the box is at the old path's cost (tick +0.8% / +0.2%, inside the runs' spread) and the bipeds' node matrices don't move (6.34 / 6.32 ms a tick against 6.32 / 6.31): means A carries no gain of its own; it closes the gap the earlier pairs showed.

**Means B** (builder/posingb; keep word `boxposeb`, only under `PSP_BOXPOSING=1`; `docs/box_posing.md` §1b; off, the box's A path is unchanged and the default EBOOT byte-identical):
- `box_posing.c`: `box_posing_make(plan, orientations, nodes, made, want)` makes the nodes of `want` that `made` lacks, with their parents: a pass from the walk's end carries each want up to a made parent (the walk's order puts every parent first), then a pass in the walk's order makes them with the walk's own `from_orientation` and `multiply`. So a node made late is the whole walk's bits (exact by construction, as LBM and VISLAZY were). `pose()` takes `want` (~0 is the whole walk, and only then are lines claimed: a claimed line is undefined until stored) and returns the nodes made. `box_posing_below` gives a node's subtree.
- `psp_box_pose` (FIXES_BOXPOSING) asks `psp_boxb_want` what to make: a living biped standing alone whose walk is whole makes its standing readers' nodes (the root, every instance of the `head` marker, the definition's head and pelvis nodes; named once a map and kept with the plan) and each attached child's node; on a frame's last tick a biped drawn last frame (vislazy's list) makes every node. Dead bipeds (the limp body, the sleep check) and riders (their vehicle's rays on the ME, past the rays' own test) pose whole. A pose that owes takes the slot of its absolute index's low byte (256 slots; another owing pose there: whole) with what it made, its model's full mask and its plan.
- Readers: `object_get_node_matrix` makes the node's chain, `object_get_node_matrices` every node, `object_get_marker_by_name` the marker's own nodes (the instances `model_get_marker_by_name`'s loop will take, by the object's permutations, up to its count, plus the root it falls back to), then reads the block past the whole make. `PSP_BOXB_READ` is the in-line test: no owing slot, no call. The IK (`object_inverse_kinematics`) makes the subtree under the arm's top node before it moves the arm, so the nodes under it are the walk's. The limp body makes its biped whole. A game state saved makes everything owed; one loaded, or a new map, forgets the slots.
- The ME never makes: `psp_boxb_me` is a copy of the slots (what was made, every bit past the model set), taken at each hand-over (`psp_nms_pending_for_me`) and at the objects' loop's end. An ME read of an owed node hands its actor back (26, as vislazy's), an ME ray at an owing biped goes to the main CPU (-1), and a read with no actor in hand is counted (`ME reads with no actor to give back`, expected 0).
- `boxposebcheck` makes every owed node before each tick's `statecrc` hash, so the whole state hash compares with A's.
- Counts: `boxposeb:` every 900 ticks (poses, owing poses, nodes made against all, late makes and IK makes with their nodes, whole poses by reason) and the late makes by reader site.

**Cut in by default** (builder/posingb-tock2, on the tock 426bdad; the lead, 2026-11-15 04:54: "cut in, default on, under PSP_BOXPOSING with its off word"):
- `psp_build.py`: `BOXPOSING` is on unless `PSP_BOXPOSING=0`, and off in the multiplayer build unless `PSP_BOXPOSING=1`, since the box hasn't been built for network play (a co-op client poses without its AI; its readers are the campaign's). The resolved switch is written back to the environment so `psp_fixups.py`, which reads it there, takes the same answer; run alone, `psp_fixups.py` resolves the same default.
- `psp_fixups.py` (`psp_boxb_want`): B is on unless `boxposeboff`; with it every node is made (means A, the box's whole walk). `boxposebcheck` still turns B on with its check. `PSP_BOXPOSEB_DEFAULT` is gone: it was the two-build pair's way to have B on without a keep word, which is now the default. The old `boxposeb` word does nothing.
- The merge itself (`psp_build.py`, `psp_fixups.py`): the tock's PSP_DEADDEBUG flag and FIXES_ARRAYFULL / FIXES_DEADXBOX sit beside B's CAPTURE_DEFINES and FIXES_CAPTURE_POSING / FIXES_BOXPOSING, B's groups applied after the tock's; every anchor matches once with and without the box.
- **Profile:** the box's two units and the changed `object_compute_node_matrices` have no counts in the tock's profile, so a `PSP_PGO_STRICT=1` build needs a profile counted with the box in. Until one is counted on the merged tock, the default build should carry B's own profile and layout (`campaign-poseb9114`, `w_poseb9114_tgc90`): counted on the tock 9114ff8 with B on, they are newer than the tock's own and cover the box.
