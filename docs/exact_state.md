# What must stay exact: the state the multiplayer host reads or checks (ledger 7)

The redesign's ledger 7 (`redesign_recon.md`), for the rule "Exactness follows the multiplayer boundary" (CLAUDE.md): state the host consumes or checks stays exact, or is proven against ChupathingyCE's host; local-only work may differ in the last bits when side-by-sides show it plays and looks the same. This page lists each piece of state that crosses the wire or is checked at join, what the host does with it, and every job on the PSP that writes it, so a job's placement or a lever's maths can be judged against it.

**Source:** a read of the engine at the pin (ChupathingyCE d98982b, network version 29): `port/linux/game/network_distributed.c/.h`, `network_objects.c`, `network_damage.c`, `network_actors.c`, `network_coop.c`; the PSP's jobs from `psp/src/psp_me.h` and `psp_fixups.py`. Builds with `PSP_MULTIPLAYER=1` are left out for now, so nothing here was compiled or run: a read only. It extends `hardware_utilization.md` §6 (the verdicts by system) with the state and the writers. Labels: [D] read in code, [U] inference.

## 1. The boundary in one paragraph

The PSP is only ever a client. A client sends the host five things: its players' input, its own player's unit (a prediction), the vehicle its own player drives (a prediction), its own players' hit reports, and at join its readiness and identity (co-op adds a cutscene skip vote) [D, the message enum in `network_distributed.h`]. The host takes each within bounds and recomputes none of them to compare; it checks no tick's state. It does check the client's **clock** (how fast its ticks come) and, at join, the **build, tags and map**; and every machine must place the map's objects at the **same datum indices**. Everything else a client computes is either the host's word copied in (and corrected toward it) or local, seen by no one else. **The AI does not run on a client at all** (game.c skips `ai_update`; a client creates no actors: `network_actors.c`), and in co-op only the host runs the scripts and decides the devices (`network_coop.c`) [D].

## 2. The state, what the host does with it, and who writes it

| State | On the wire | What the host does | Jobs that write it on the PSP (unit) | Verdict | |
|---|---|---|---|---|---|
| **The client's clock** (the tick stamped on its input and predictions) | client -> host, each message | measures the client's ticks against its own every 2 s: running over 1.1x fast and over 15 ticks ahead refuses its predictions, five such windows on its stream drop it (`distributed_note_client_clock`). Slow is never refused | the main loop's tick pacing (main CPU) | **must match**: 30 Hz, never fast; a tick that runs long is safe | [D] |
| **Players' input** (`player_action`: buttons, aim, throttle; the tick, the latest host tick heard, co-op's BSP index) | client -> host, every tick, with the last ticks' buttons | runs it as given, clamped (`network_distributed.c`); nothing recomputed | input poll and `player_control` (main CPU) | **the client's word**: any maths that builds it may differ | [D] |
| **Own player's unit** (position, velocity, forward, up, the tick it was at) | client -> host, every tick | takes it within 3.5 units of its own (`HOST_ACCEPT_TOLERANCE`), at most 2.0 units a tick, on foot 2x a run and jump + 0.05, no more than 1.0 above the ground it last had (`PREDICTED_*`); the client is put where the host has it past 3.0 (`LOCAL_CORRECTION_TOLERANCE`) | the biped's `unit_update`: its physics and its collision against the BSP and objects (main CPU); the input above | **bounded**: last-bit drift is far inside 3.0; a systematic collision difference (the packed tree) would show as snaps | [D] |
| **Own player's vehicle** (where it drives it, at which tick) | client -> host, every tick | takes it within what the vehicle can move by its next tick, 5.0 units (`HOST_VEHICLE_ACCEPT_TOLERANCE`); the client is moved by the gap only past 4.0 (`LOCAL_VEHICLE_TOLERANCE`) | the vehicle's physics in `unit_update` (mass points' ground queries and rays, main CPU) | **bounded** | [D] |
| **Hit reports** (target object, damage: its definition, origin, epicenter, scale; where the shooter had the target, the normal, node, region, material; the host tick it had heard) | client -> host, reliably | checks the target within 3.0 units (+15 ticks' movement) of where it had it, the impact within 2.0, the shooter within 2.0 of its history (+3 ticks; vehicles 4.0), the source within 6.0 of the firer, origin and epicenter within 0.01, everything finite and inside 32,768, the scale bounded (`network_damage.c`); then deals the damage itself | projectile update and its collision rays (main CPU); melee in `unit_update` (main CPU); the model's collision, which reads the node matrices: built on the main CPU from base poses the ME prepares a tick ahead (ME_JOB_POSES, `#poseahead`) | **bounded**; node, region and material pick the damage's multiplier and are passed as the client found them [U: no bound on them was found] | [D] |
| **Own ammunition and grenades** | host -> client (inventories) | the client spends its own; it takes the host's count only after a round trip (`network_objects.c`) | the weapon's fire in `unit_update` (main CPU) | **the host's word** after a round trip | [D] |
| **Placed objects' datum indices** (the map's objects at load, identifier and all) | names in every object message | every machine places them as the host did, at the same indices; the host's word finds them there (`network_objects.c`) | map load's object placement (main CPU); the bake's order of the scenario's objects | **must match, discrete**: whether a Sierra-III bake keeps the order is unchecked (§6) | [D] |
| **Build, tags and map** (the join token: build time mixed with `tag_groups_checksum()` in non-DEBUG builds; the map's version; network version 29) | client -> host at join | refuses a mismatch | the build and the bake; `psp_limits.h` moves with the engine's pin | **must match, discrete**; the token's size is pointer-sized (4 bytes on the PSP), unchecked against the host's 8 (§6) | [D] |
| **The client's own objects** (projectiles, effects' objects) | never | none: indices from the array's upper half, which the host's don't reach in practice; deleted once the host's objects are all told | projectile and effect updates (main CPU); particles' and contrails' physics on the ME (ME_JOB_POINTS) | **local** | [D] |
| **Other players, vehicles, items, bodies** | host -> client (unit states, object states, inventories) | its own word: the client glides to it under 1.0 unit, half the gap a tick, jumps past it (`network_objects.c`) | the receive and interpolation (main CPU); remote units run through `unit_control` and `unit_update` between messages (main CPU) | **local, corrected** | [D] |
| **AI units** (the host's actors' control and state) | host -> client (actor states, actor damage, damage animations) | its own word; the client feeds the control into `unit_control` as for a remote player, the state corrects drift (`network_actors.c`) | as other players' units; the client's AI jobs don't run (AIME on the ME, perception rays on the ME, `actor_update` on the main CPU) | **local, corrected**; the AI itself is outside the boundary | [D] |
| **Damage, death, shields, health** | host -> client (damage events, unit states' vitality) | the host deals all damage; the client deals none | the client replays the host's damage for its effects (main CPU) | **the host's word** | [D] |
| **Pickups, swaps, drops** | host -> client | the host decides; the client decides none (`network_objects.c`) | none on the client | **the host's word** | [D] |
| **The game type's state, scores, statistics, pings** | host -> client | its own word | none on the client | **the host's word** | [D] |
| **Co-op: scripts, cinematics, camera, devices, BSP, objects' transforms and looks, screen effects** | host -> client (the coop messages) | only the host runs the scripts and sets the devices; a player's use of a switch is relayed to it (`network_coop.c`) | none on the client beyond applying them (main CPU); the client's BSP index goes back in its input | **the host's word** | [D] |
| **Node matrices, animation, poses** | never | reach the host only inside hit reports (above) | main CPU; next tick's base poses on the ME (ME_JOB_POSES) | **local** | [D] |
| **Particles, contrails, decals, lights, sound, effects, HUD** | never (no message kind) | none | particles' and contrails' physics on the ME (ME_JOB_POINTS); the mixer on the ME (ME_JOB_AUDIO, ME_SLOT_AUDIO) and sound pieces' copies (ME_JOB_SOUNDCOPY); effects, lights and decals on the main CPU | **local** | [D] |
| **Visibility, drawing, the record and its replay** | never | none | the visibility (main CPU; again on the ME in `mevis`, ME_JOB_VISIBILITY); the GE layer's calls on the ME (ME_JOB_GE), angle sort (ME_JOB_ANGLE, ME_JOB_SLANT), classify (ME_JOB_CLASSIFY), the replay (ME_SLOT_RENDER); the GE | **local** | [D] |
| **Randomness** (the game's random seed) | never | none: the host's word carries every outcome that matters (damage, pickups, the AI) | every job that draws a random number | **local** [U: no seed or random state was found on the wire] | [U] |

## 3. By job: which boundary state each writes

| Job (unit) | Boundary state it writes | So its maths |
|---|---|---|
| Biped physics and collision, `unit_update` (main CPU) | own player's unit (bounded 3.5); hit reports' positions through melee (bounded) | may differ in the last bits; collision stays exact anyway by the project's rule (Sheepdog01 10-30: one path, every mode) |
| Vehicle physics (main CPU) | own vehicle (bounded 5.0) | may differ in the last bits |
| Projectile update and its collision (main CPU) | hit reports (bounded 2-6 units, finite) | may differ in the last bits, collision included (Sheepdog01 2026-11-09 17:30/17:52 retired "collision exact"; CLAUDE.md, the multiplayer boundary) |
| Node matrices (main CPU) and next tick's base poses (ME_JOB_POSES) | hit reports' node, region, material, through the model's collision | local but feeds an unbounded pick [U]: a systematic bias would go unnoticed (§6's riskiest call 2) |
| Input and `player_control` (main CPU) | input (clamped) | the client's word |
| Tick pacing, the main loop (main CPU) | the clock (never over 1.1x, 15 ticks ahead) | rate must hold; content free |
| Map load's placement (main CPU), the bake | placed objects' indices; tags and map at join | discrete: must match |
| The AI: AIME (ME_SLOT_AI), perception rays (ME_JOB_PERC_RAYS), `actor_update` (main CPU) | none: not run on a client | free on a client (the campaign's own rules apply) |
| Particles' and contrails' physics (ME_JOB_POINTS), effects, lights, decals (main CPU) | none | local |
| The mixer and sound copies (ME_JOB_AUDIO, ME_JOB_SOUNDCOPY, ME_SLOT_AUDIO; music) | none | local |
| Visibility (main CPU, ME_JOB_VISIBILITY), the GE layer's calls (ME_JOB_GE), angle sort (ME_JOB_ANGLE, ME_JOB_SLANT), classify (ME_JOB_CLASSIFY), the replay (ME_SLOT_RENDER), the GE | none | local |

**So:** no job on the ME writes state the host reads, except the base poses a tick ahead, which reach it only through the hit reports' node, region and material [D + U]. Every job the redesign might move between the main CPU, the VFPU and the ME is free of the bit-exact rule on a client, so long as the play stays the same (the side-by-sides) and four things hold: the tick never runs fast, the placed objects keep their indices, the tags and map match at join, and collision's answers (the project's rule) stay exact.

## 4. Open

1. Whether the host bounds a hit report's node, region and material at all (read `network_damage.c`'s receive whole) [U].
2. Whether a Sierra-III bake keeps the scenario's object order (§6; a host-side load of a PSP bake would settle it) and the join token's size on the PSP.
3. The random seed: whether any message or check depends on it [U].
4. Co-op (the end goal) adds the host's actors to every client: AI units arrive as states, so the client's AI cost is gone there, but their units' `unit_update` and drawing stay (ledger 2 prices both).
