How these numbers were made

  • Stage times: b114 test 1's profile.txt [M], 65 windows of 10 s, each step timed until the next, so the steps add up to the frame by the clock. Windows are placed in a stretch by their cumulative ticks, which blurs each edge by up to one window. One run, hand-played: outside the cutscene, runs of one build vary by about 7%.
  • A tick's split by object type, the memory waits by phase, the GE's busy time and the Media Engine's share: the same run's log lines (objects_update by type, hwprofile, gebusy, ME) [M].
  • "What it's made of" inside a stage: the emulator's cache model on b114 (lab run 38125250298, all of b30 with fixed ticks) [E]. Shares are of that phase's instruction fetches (the work) and misses, over the whole level, so they point to where, not to how many milliseconds.
  • Targets: Sheepdog01's, 2026-10-11. A steady 30 ticks a second needs two ticks plus a frame's drawing in 66.7 ms; 30 fps needs one tick plus drawing in 33.3 ms. Halo caps a frame's game time at 1/15 s (main.c), so a frame carries at most two ticks and the game slows below 15 fps [D].
  • Xbox figures are its published hardware; how Halo used it is read in the engine's Xbox rasterizer code [D].
